Jev as a decision layer for OpsAssist

A proposal to put Jev by TypeSafe, a hosted API that answers typed decision questions with probabilities, around the assistant's existing router and answer checks. Jev would rank and choose between paths that are all already safe. Authorization, isolation, approvals, egress and audit stay in code and in the database, as the brief requires.

01What Jev is, as far as we have read

From the playbook code we read (src/jev_client.py, src/router.py):

  • TypeSafeClient.system_one(state, questions) takes a compact state and a set of typed questions.
  • It answers each question with one of three types:
    • Choice picks a label;
    • Score rates on a scale;
    • Noul gives the probability of yes or no.
  • A router of our own maps those answers to actions using confidence thresholds.

The playbook's default policy:

  • ≥ 0.80: act on the decision;
  • 0.50–0.79: treat it as a recommendation;
  • < 0.50: escalate to a human;
  • shadow mode logs the advice without acting on it.
Sources. The official instructions are docs.typesafe.ai and github.com/typesafe-ai/skills. The playbook (github.com/Bodila51/muse-jev-playbook) is a personal repository with a single commit. Treat it as a reference, not a dependency, until it is reviewed. Latency, data retention and whether an on-premises deployment exists are not yet verified. Those three facts decide how much of this proposal is possible.

03Proposal: decision points

Each row is one question Jev would answer. The fallback column is what the assistant does today, and what it keeps doing whenever Jev is off, slow, unsure or unavailable.

⑤ Correct a false premisethe largest remaining failure: M01, M04, H27 Noul accepts_false_premise Question, answer, cited passages ≥ 0.80 re-answer with the premise corrected, cited · otherwise return Abstain or answer without correcting not for confidential
⑥ Judge the near missesthe gate review of PR #19 Choice which passage answers, or none Question and up to 3 passages Admit only passages chosen at ≥ 0.80 Local 3B judge not for confidential

Rows ④–⑥ send document text. They run only when allows_egress passes for the whole conversation (migration 0009). Every other conversation keeps today's local checks. A deployment that allows no egress at all turns Jev off with one setting.

A fresh held-out suite, ideally written by someone who has not seen the failures, is needed before phase 2. The current one has already been used for two fixes (H17, H34).

08Open questions

  • For TypeSafe: how long is request data retained, and is it used for training? Is there an on-premises or VPC deployment? What are the latency and throughput limits per key?
  • For the team lead: may question text (never documents) go to Jev for internal users? Which decision point matters most: routing or false-premise correction?
  • For us: does a probability on the route beat the current code guards on cases they were not written for?

The installation prompt this proposal started from is copied unchanged in JEV_prompt.md. It installs Jev into a coding agent (Claude Code, Codex, Cursor) to decide its own next steps. It was read, not executed. This proposal applies the same idea to the assistant's request path instead.
