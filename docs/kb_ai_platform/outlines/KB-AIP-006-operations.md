# Operations and Deployment

**Scope:** how the stack runs, how to tell it is healthy, and how to change it safely.

## 1. The stack
- **Docker Compose:**
  - the API;
  - the ingestion worker;
  - Postgres with pgvector;
  - Redis;
  - optional profiles for tracing and a demo client.
- **One image serves both the API and the worker.**
- **Configuration:**
  - every setting has a safe default in `.env.example`;
  - settings are typed and validated at startup;
  - production rejects development-only settings.

## 2. Health
- **Liveness** (`/healthz`) says the process is up, and never checks dependencies.
- **Readiness** (`/readyz`) checks Postgres (pgvector and migrations) and Redis, and returns
  503 with detail when one fails.

## 3. Logs and correlation
- **One JSON line per event.**
- **Every request carries a request id:** a caller's id is kept only if it is log-safe;
  otherwise a new one is issued. The id is returned in `X-Request-ID` and appears on every
  log line.

## 4. Metrics
- **Prometheus at `/metrics`:**
  - HTTP requests and latency;
  - model calls, latency and tokens;
  - tool calls by tool, decision and outcome;
  - retrieval latency;
  - rate-limiter rejections and unavailability.
- **Labels are bounded:** route templates, not raw paths; an unknown tool name counts as
  `unknown`.
- **Per-attempt model usage is in the `llm_usage` table.**

## 5. Database changes
- **Migrations are append-only,** one per feature, in build order. An applied migration is
  never edited; a schema change is a new migration.
- **Do not generate migrations blindly.** The database holds objects the ORM models do not
  declare:
  - vector and full-text indexes;
  - generated search columns;
  - the agent's checkpoint tables.

  An autogenerated migration would drop them.
- **Two database roles:** migrations and seeding run as the owner; the API and worker run as
  a non-superuser role.

## 6. Background work
- **The ingestion worker:** jobs recorded in `ingestion_jobs`, retries for transient
  errors, immediate failure for permanent ones, a dead-letter queue.
- **Inspecting jobs:** `make jobs` shows the recent ones.

## 7. Clients
- **The console** (`/ui`) exists only in development and test. It holds no policy and no
  credentials; it renders what the API returns.
- **Flowise** is a client of `/api/chat`, not the orchestrator.
- **CubeJS is not used.**

## 8. Everyday commands
- `make up`, `make reset`, `make ingest`, `make lint`, `make test`, `make test-integration`,
  `make test-security`, `make eval`, `make logs`.

## Excluded from this page
- Hostnames, passwords and environment values beyond variable names.
- Test counts and CI run results.
