Questions the panel is likely to ask

Twenty questions with a short answer to say out loud, the evidence to point at, and the phrasing to avoid. The brief says the candidate must understand and defend every submitted design decision and document incomplete areas honestly, so every answer ends on something you can show.

QuestionWhat to sayPoint toAvoid
Why pgvector inside Postgres, not a dedicated vector database?Architecture Permissions, document versions and vectors live in one transaction, and row-level security covers retrieval itself, so a forgotten filter still returns nothing. At 1M documents the index is ~84 GB; partitioned by department it is ~8.4 GB each, which fits. A dedicated store is step two, and its cost is explicit: isolation leaves the database. D-01, D-22, D-60 sizing table; make capacity "pgvector is faster." It was chosen for isolation and transactions, not speed.
Why LangGraph? Does the agent decide what is allowed?Architecture LangGraph gives a durable pause and resume: a VPN request waits for a second person across restarts through interrupt() and a Postgres checkpointer. The graph only chooses a path. Policy, tool schemas, pending actions and the audit log sit outside it and are unit-tested without a graph. D-26; agent/graph.py, agent/service.py "The agent handles permissions." It never does.
Why write your own model gateway instead of using LiteLLM?Architecture The behaviour I have to defend lives there: retry with backoff, fallback chains, a circuit breaker per model, the egress rule by data classification, and a usage row for every attempt. Owning it keeps those rules testable and explainable. Providers are adapters behind one interface: NIM, Ollama, Claude and a deterministic mock. D-10, D-11, D-14, D-15; demo step 5 "LiteLLM is bad." It was a scope and control trade-off, not a verdict.
What happens if a provider fails in the middle of a streamed answer?Architecture Fallback is allowed only before the first token. After that, switching models would splice two answers together, so the stream ends with a controlled error that carries the request id and no provider error text. D-13; api/chat.py stream path "It seamlessly continues on another model."
How did you choose chunk size and overlap?RAG By measurement. Parent–child chunking (a ~64-token chunk is matched, its ≤256-token section is given to the model) was compared with per-page, fixed-window, structural and Docling chunkers on a gold set of 41 questions. The gain came from heading-aware sections; chunk size matters little (hybrid Hit@1 0.878–0.927 across 32–128 tokens, overlapping intervals). Production uses 64: Hit@1 0.927, MRR 0.963. D-20; evaluation/reports/chunking.md "512 tokens is the industry standard."
Why nomic-embed-text and not a stronger embedding model?RAG Measured against NVIDIA nemotron-3-embed-1b on 40 gold cases, with confidential documents excluded so nothing restricted went to the API. With vector search alone nemotron ranks better (0.950 vs 0.825), but in the hybrid mode production runs they are identical (0.925 Hit@1). Nomic runs locally, sends nothing out, and is faster and cheaper. Experiment in PR #13 (closed: decision unchanged); D-20 "We never compared." We did, and the answer is no difference where it matters.
How do you know a citation isn't made up?RAG Three checks in code. A citation marker must point at a source that was retrieved for this user. A citation whose section lacks the figures in its sentence is moved to the retrieved section that has them, and the response counts it. An answer with no citation is flagged and counted as a miss. Judged per citation, 35 of 35 supported their exact claim. rag.py finalize, repoint_citations; D-20 "The model always cites correctly." It does not; the backend checks it.
What happens when a document is replaced?RAG An unchanged content hash is a no-op. A new version is indexed and then swapped in atomically, so there are never two active copies. Failed ingestion jobs retry and then land in a dead-letter queue, and the old version stays active. D-23, D-24; knowledge/ingest.py "We delete and re-insert." That would leave a window with no document.
Can the model create a VPN profile on its own?Tools & approval No. The model can only propose. A sensitive tool becomes a pending action: permissions are checked, and a different person with vpn:approve must confirm. The confirmation carries a hash of the exact arguments. It executes once, a second approval says "already executed", and every decision is in a hash-chained audit log. D-31, D-32; demo step 3; /api/audit/verify "The prompt tells it to ask for approval." The approval is enforced in code.
What if the router picks the wrong route or tool?Tools & approval The router only picks a path; schemas, permissions and approval come after it. A wrong "tool" is rejected, denied or held for approval, and a wrong "refuse" is unhelpful but never unsafe. A real case: the brief's own example, "…John Tan - with approval", was refused because the 3B router matched "approval" to "skip approval". It was fixed with a rule, not with examples: mentioning an approval is not bypassing it. When the model later invented an argument, approval_needed: false, the strict schema rejected it. D-28, D-34; PR #15 "The router can't be wrong."
Is tool execution idempotent?Tools & approval Yes, where it matters. A repeated ticket request within the window returns the existing ticket. An approved action runs once; approving it again is denied. Tool results shown to the user are rendered from the stored record, not summarized by the model, so success cannot be invented. tools/executor.py; test_ticket_is_created_once… "The model reports the result." The server renders it from real data.
How is department isolation enforced?Security Two layers below the model: a SQL scope filter, and Postgres row-level security under a non-superuser runtime role. A test found that a superuser bypassed RLS, and a migration fixed it. Confidential material is in a separate table and goes only to local models. An Engineering user gets nothing, not even a title: isolation held in 10 of 10 cases. D-17, D-22, D-15; demo step 6 Anything that sounds like "the prompt tells it not to show HR data". The brief calls that unacceptable.
How do you resist prompt injection from documents?Security Retrieved text is untrusted data: it is escaped inside source tags and has no authority. The knowledge path has no tools at all, and tool calls are authorized outside the model. The malicious document is retrieved (it is legitimate content), its instructions are not followed, and "skip confirmation" still ends as a pending action. D-25; demo step 4; make test-security (105 tests) "The model is trained to ignore injections." The defence does not depend on the model.
Where are secrets, and can they leak?Security Secrets come from the environment and are typed SecretStr, so they never appear in repr or logs. They never go to the model. Staging and production refuse the dev JWT secret or any secret under 32 bytes. Persistent memory rejects credential-shaped values. The repository contains no real keys. config.py; D-40; test_config.py "We rely on developers not to commit keys."
Why 68–69/73 and not higher? And what is 63/71?Evaluation 68–69/73 is the current system across two clean runs under judge-v2, with no evaluation content in any prompt; nothing was adjusted, and it is 69–70/73 by hand (one judge error). The runs differ by one case, on how the 3B model worded an answer, so the honest figure is a range. Isolation is 10/10 and tool accuracy 34/34, graded by rules. The failures left: two false-premise questions answered by abstaining (a product decision with the team lead), a two-part question and a refusal worded by the model (PR #14). 63/71 is the earlier D5 run under judge-v1: a different measurement regime, kept as a reference, not a before/after. router-3b-run.md, rules-only-run.md, D-34; analysis.md "We went from 63 to 69." Or quoting a single run as if it were exact. Different judge, different prompts, different suite.
Why trust an LLM judge?Evaluation It grades only prose; safety is graded by rules. Three separate graders answer three questions: is this reference fact conveyed, does this citation support this sentence, and did the answer assert anything outside its sources. The judge is a different model family, runs locally, and must quote the answer. Code discards what it can check itself: a "contradiction" whose own quote states the fact, and an "unsupported" claim that is in the passage. The judge was also measured against hand labels on fixed answers: v1 35/39, v2 36/39. evaluation/judge.py, judge-drift.md, judge_labels.jsonl (PR #15) "The judge is always right."
Did you tune your prompts to your own evaluation set?Evaluation We found that we had. The router's examples overlapped 10 evaluation questions, and the judge's example was the reference answer of 3. We removed them, and now prompts hold only rules; tools reach the router as skill cards generated from code. A test fails if any prompt shares wording with an evaluation question or answer, or names a sample record. We then re-measured by regime, not as a delta. On the same answers the judge rubric changed one decision. Without examples the router first got weaker: one request opened a ticket nobody asked for. A guard in code now holds back any skill that writes when the request never names its record, and tool accuracy is back to 34/34, still with no examples in the prompt. D-34; test_prompt_hygiene.py; rules-only-run.md (PR #15) "Our prompts are generic." Say what was found and what it cost.
How does this scale to 5,000 employees and 1M documents?Scale The architecture is unchanged; each tier scales on its own. Sizing is generated from stated inputs: ~47M chunks, an ~84 GB index partitioned by department, and 10 L4 GPUs (4 × g6.12xlarge, N+1) at the 100-request ceiling. The ceiling is about 13 times the expected average, so GPUs autoscale on queue depth with a floor of two. Confidential data stays on vLLM inside the VPC. D-60 with its AWS diagram; make capacity "It's been load-tested." It has not; say which three measurements come first.
What would you do with one more week?Limits Correct false premises instead of abstaining (a product decision to agree first); escalate streamed answers too; replace the dev token issuer with OIDC; give the API and the worker separate database roles; run the load test D-60 names; route knowledge-gap tickets to a named owner. README "Known limitations"; analysis.md "What is still open" "Nothing, it's finished."
